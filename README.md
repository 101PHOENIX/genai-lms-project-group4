# GenAI & LMs — Practical Project · Group 4

UPM MUCD · Generative AI and Language Models · 2026-27
Challenge: design and develop a video game using generative AI tools.

> **Status:** vertical slice of the case-generation pipeline + engine-free game rules (30/30 tests).
> Unity UI, NPC dialogue prompt and final art are not built yet. See [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

## Concept

Single-player 2.5D anime murder mystery set in a locked boarding school. The player is the
Detective; the cast are the team members. **Every playthrough is generated by an LLM**: for
each case the model secretly writes the full truth (victim, killer, motive, clues, lies of
every NPC) as a JSON *case file*. The game never shows that file. The player uncovers it over
7 dice-limited investigation rounds and then votes at a trial.

Two design rules hold the whole thing together:

1. **The LLM proposes, the game disposes.** Model output is validated against a schema and
   game-logic rules before the game uses it. Model text never writes game state directly.
2. **Every prompt change is measured.** Each change to a prompt or model is benchmarked and
   logged with the KPI it moved (`PROMPT_LOG.md`, `ITERATION_LOG.md`, `baselines/`).

## How to run

Requirements: Python ≥ 3.10 (standard library only), .NET SDK ≥ 8 for the tests, Unity 2022+ for the game.

```bash
# 1. Validate a case file against the schema + game rules (exit code 0 = valid)
python tools/validate_case.py narrative/sample_case.json

# 2. Design audit: is it a fair, solvable mystery? (solver + dice probabilities)
python tools/audit_case.py narrative/sample_case.json baselines/baseline-v1-pollinations/run*.txt

# 3. Benchmark the generator (writes baselines/<label>/ + summary.json)
python tools/benchmark_llm.py --provider pollinations --runs 10 --retry      # free, no key
GEMINI_API_KEY=... python tools/benchmark_llm.py --provider gemini --runs 20 --retry
GROQ_API_KEY=...   python tools/benchmark_llm.py --provider groq   --runs 20 --retry

# 4. Benchmark live image generation (free tier: 1 image / 45 s per IP)
python tools/benchmark_images.py --runs 6

# 5. Game-rule unit tests (Core compiled at C# 9, same as Unity)
dotnet test tests/CoreTests
```

API keys go in environment variables or a gitignored `.env`. Never in code.

### Using Core in Unity

Keep `unity/Assets/Scripts/` inside the Unity project's `Assets/`. `Core/` has no
`UnityEngine` dependency; the UI only reads state from and calls into `CaseSession`:

```csharp
var session = new CaseSession(caseFile, detectiveId, aliveIds, new RandomDice());
session.BeginInvestigation();                          // after the discovery sequence
var allowance = session.RollForRound();                // show dice + word limit
string why = session.CheckAction(text, npc, usesOwnSkill, asksNpcSkill); // null = OK, else show reason
// ... send to LLM, get {reply, trust_change, revealed_clues}
session.CompleteAction(npc, trustChange, revealedClues);
// when session.Phase == CasePhase.Trial -> voting screen -> session.Vote(id or CaseFile.SuicideVote)
```

## Layout

| Path | Contents |
| --- | --- |
| `narrative/master_system_prompt.md` | Master System Prompt: the case-file generator (version history in the logs) |
| `narrative/game_context.json` | World state sent with every request (cast, alive, detective, locations). Skills are **placeholders** |
| `narrative/sample_case.json` | Hand-written valid case file: the contract between Narrative and Unity |
| `tools/validate_case.py` | Schema + logic checks. Answers *"is this JSON legal?"* |
| `tools/audit_case.py` | Design audit. Answers *"is it a fair, playable mystery?"* |
| `tools/benchmark_llm.py` | N generations → JSON validity / logic pass / latency KPIs, 3 providers |
| `tools/benchmark_images.py` | Live image success rate + latency (Pollinations) |
| `unity/Assets/Scripts/Core/` | Engine-free rules: dice tiers, word limiter, trust, 7-round `CaseSession`, case-file model |
| `unity/Assets/Scripts/Net/LiveImageQueue.cs` | Rate-limited image prefetch with timeout + offline fallback |
| `tests/CoreTests/` | xUnit tests for Core (30 tests) |
| `tests/injection/` | Fixed prompt-injection attack set for the NPCs and how to score it |
| `baselines/` | Raw benchmark outputs, one folder per run, with `summary.json` / `audit.json` |
| `dialogue/` | LLM-driven NPC dialogue module (schema proposal) |
| `docs/ARCHITECTURE.md` | How the pieces fit, why they were built this way, known limits |
| `docs/self_critique_jury.*` | Simulated 5-juror critique of the project (EN; `autocritica_jurado.*` is the ES version) |
| `docs/TASK_DISTRIBUTION.md` | Workstreams, roles, checkpoints |
| `docs/SUBMISSION.md` | Outline of the Moodle PDF, one section per rubric criterion, with its sources |
| `.github/workflows/ci.yml` | Validates the sample case file and runs the Core tests on every PR |
| `PROMPT_LOG.md` | Prompt iterations with justification. **Everyone adds entries** |
| `ITERATION_LOG.md` | One row per change to a prompt, model, pipeline or build, with the KPI it moved |
